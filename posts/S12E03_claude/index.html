1 Introduction

1.1 What we’ll cover

In the previous session, we used AI through Posit Assistant and GitHub Copilot in Positron to help you make plots. Today, we’ll use a different kind of AI tool: Claude Code, Anthropic’s “agentic” coding tool, which we’ll run inside Positron.

We’ll start small, by having Claude write a script for a single plot, and work our way up to tasks that would take you quite a while by yourself: cleaning up a messy dataset, writing a Quarto report with plots and nicely formatted tables, giving it Ohio State branding, and building a small Shiny app. Specifically, we’ll cover:

  • Setting up Claude Code in Positron with an OSU API key
  • Having Claude write, run, and check R code
  • Giving Claude your files as context
  • Stopping, steering, and rewinding Claude while it works
  • Persistent instructions with a CLAUDE.md file
  • A mini-project: from a messy CSV to a branded Quarto report and a Shiny app

The appendix covers managing context and cost, good habits when working with an agent, and a bonus exercise in which Claude finds and fixes bugs.

We picked these tasks because they are a sweet spot for AI help: hard to write, but easy to check. Polished tables, interactive plots, and Shiny apps take a lot of code, using packages and syntax that most of us don’t use often enough to remember. But you can tell at a glance whether a plot, a table, or an app looks and works the way you want. Compare this with, say, a statistical analysis, where code can run without errors and still give subtly wrong results that are hard to spot.

1.2 From chat to agents

When you use AI through a browser-based chat, the model can’t see your files unless you paste or upload them, and it can’t check whether the code it writes actually works. AI agents, on the other hand, can work inside your editor and:

  • Read the files in your project, so you don’t have to explain or paste them
  • Edit and create files, showing you each change for approval
  • Run code and commands, and then look at the results, including errors and even the plots they made
  • Hack HuggingFace 😱

1.3 Posit Assistant vs. Claude Code

Posit Assistant, which we used in the previous session, is also an agent. In fact, it has a key built-in strength that Claude Code does not have: it is connected to your live R session, so it can see your objects and run code in your console1.

On the other hand, Claude Code has the edge in other areas:

  • It is a general-purpose coding agent and is designed also with longer-running, multi-step tasks in mind.
  • It is a more mature product overall. For example, we’ve had authentication problems with Posit Assistant, both via GitHub and with an API key, but not with Claude Code.

(Claude Code also comes in other forms, like a command-line program and a desktop app. Here, we’ll use its VS Code extension in Positron.)

1.4 Authentication with an API key

Rather than using a personal account, we’ll authenticate through an API key from OSU’s Generative AI Service , which is approved for use with restricted institutional data (S2–S4)2. We’ll give you a personal API key for this session with limited credit.

If you’d like to continue using Claude Code or Posit Assistant in this manner after today’s Code Club, you’ll have to set this up via the link above — but keep in mind that it isn’t free, so your PI (or similar) would need to have funds that can be used for this purpose.

Alternatively (or additionally), you could get a personal Anthropic subscription. Per token, this is a lot cheaper than usage with an API key, but you’ll need to pay personally and you shouldn’t use it with institutional data.

2 Getting set up

2.1 First installations

If you haven’t done so already, please:

  1. Install Positron and R version 4.5.0 or higher — see the Positron session for details. (We’ll use the penguins data that is built into R since version 4.5.0.)

  2. Install Quarto. Positron comes with its own copy of Quarto, but Claude can’t find that copy when it runs commands, so it needs a regular Quarto installation to render documents.

  3. Install the R packages we’ll use:

    install.packages("tidyverse")
install.packages("gt")
install.packages("shiny")
install.packages("bslib")

    We’ll leave a few other packages that Claude will likely want to use uninstalled (countrycode, gtExtras, and ggiraph), so you can see how Claude asks before installing packages.

NoteWindows users: Git for Windows (optional) (Click to expand)

On Windows, Claude Code runs commands with PowerShell by default. If you have Git for Windows installed, it will use Git Bash instead, which is what it does on Mac and Linux. Both work for today, so there’s no need to install Git for Windows just for this session.

2.2 Download and open the project folder

  1. Download this zip file and unzip it. You may want to move the resulting codeclub-claude folder into a folder for Code Club, e.g. Documents/codeclub/codeclub-claude.

  2. Open the codeclub-claude folder in Positron with File > Open Folder..., and trust the folder when asked.

The folder contains the following files:

codeclub-claude
├── factbook.csv        # World Bank data from the previous session
└── penguin_summary.R   # A script with some problems...

Claude treats the folder that is open in Positron as its “workspace”: this is where it will look for files, and by default the only place where it can make changes.

2.3 Install the Claude Code extension

  1. In the Extensions view in the Activity Bar, search for “claude”, and click Install for the extension “Claude Code for VS Code” by Anthropic.

  2. If asked whether you trust the publisher “Anthropic”, click Trust Publisher & Install.

2.4 Connect Claude to your API key

To tell Claude to use your API key, you need a settings file called settings.json in a folder .claude in your Home folder. Claude reads this file every time it starts up.

Let’s set this up:

  1. Create the folder and the (empty) file, and open the file in the editor, by copying the code below into the Positron console and pressing Enter 3:

    # Get your Home folder (on Windows, R's "~" points to Documents instead)
home <- if (.Platform$OS.type == "windows") {
  Sys.getenv("USERPROFILE")
} else {
  path.expand("~")
}

# Create the .claude folder and the settings file
# (an existing settings file is left alone)
settings_file <- file.path(home, ".claude", "settings.json")
dir.create(dirname(settings_file), showWarnings = FALSE)
if (!file.exists(settings_file)) file.create(settings_file)

# Open the file in the editor
file.edit(settings_file)

  2. Paste the following contents into the file that opened in the editor:

    ~/.claude/settings.json
    {
  "env": {
    "ANTHROPIC_BASE_URL": "https://litellm.cloud.osu.edu",
    "ANTHROPIC_AUTH_TOKEN": "API-KEY",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "claude-opus-5-5",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "claude-sonnet-5",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "claude-haiku-5-5",
    "CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS": "1"
  },
  "model": "sonnet",
  "effortLevel": "medium",
  "outputStyle": "Concise",
  "theme": "auto"
}

  3. Replace the placeholder API-KEY with your personal API key as shown below, and save the file:

    ~/.claude/settings.json (excerpt - with fictional API key)
        "ANTHROPIC_AUTH_TOKEN": "bY-7jiuWbfck9DZk34hA_t",
NoteMore about the settings file (Click to expand)

The file is in JSON format, a plain-text format with key-value pairs: a colon : separates each key from its value, pairs are separated by commas, and curly braces {} group pairs. A single missing quote or comma breaks the whole file (this would be a likely culprit if Claude doesn’t pick up your API key).

  • ANTHROPIC_BASE_URL makes Claude go through OSU’s service rather than directly to Anthropic.
  • ANTHROPIC_AUTH_TOKEN is the API key.
  • The MODEL lines specify which model versions to use.
  • CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS turns off experimental features that OSU’s service doesn’t support, and that would otherwise cause errors.
  • model and effortLevel set the default model (Sonnet) and effort level (Medium).
  • outputStyle makes Claude’s answers shorter and more to the point (remove this line if you prefer longer explanations).
  • theme makes Claude’s colors follow your computer’s light or dark mode.
ImportantTreat the API key like a password (Click to expand)

Anyone with your key can use it, and usage costs money and depletes your key’s budget. So never share your key or commit it to a Git repository. That’s one reason the settings file is located in your Home folder, and not in a project folder that others may see.

2.5 Open Claude

Open Claude Code by clicking the Claude icon at the top of the secondary (right-hand) side bar — the one with the blue line under it in the screenshot below:

TipAlternatively, open it in the editor pane (Click to expand)

You can also click the orange Claude icon in the top-right corner of the editor. This opens Claude as a tab in the editor, which has two potential advantages:

  • You can have multiple Claude tabs, i.e. multiple conversations, open at the same time, instead of having to switch between conversations in the same tab.

  • You don’t have to switch back and forth between Claude and the Variables, Plots, and Help panes, which share the secondary side bar.

On the other hand, things can get a bit more chaotic with Claude as a tab, and it has less vertical space than the secondary side bar.

In the Claude panel, you may initially see various login options (left screenshot below), but if you simply wait, Claude should read your settings file, and you should see a prompt box at the bottom of the Claude tab (right screenshot below):

To check that Claude works, type the following prompt in the box and press Enter:

Write a horoscope for a dataset with 40% missing values

If you get a horoscope back, Claude is set up correctly.

If you get an error instead, or Claude merely keeps printing verbs like “Brewing” and “Deliberating” (Claude’s variant on a spinning wheel) but nothing else, let us know, and we’ll help you troubleshoot.

3 Basics of the interface

The buttons across the bottom of the prompt box are, from left to right:

  • + adds files as context to your prompt.

  • / opens the command menu, with nearly all of Claude Code’s options and settings.

  • A clock icon with a number of minutes appears once Claude has responded (see the section on cost).

  • Sonnet 5 Medium is the current model and effort level. Keep it at that, and don’t select “Default (recommended)”, which switches to the much more expensive Opus model.

  • Manual is the current permission mode (what Claude is allowed to do without asking you first).

At the top of the Claude tab, there are buttons to see your previous conversations (clock icon) and to start a new conversation (chat icon with a +). We’ll start a new conversation for each new task — you’ll see why later.

NotePermission modes (Click to expand)

Click on the permission mode to switch between modes:

  • Manual: Claude asks permission for each file edit and for most commands (it runs simple read-only commands without asking).
  • Edit automatically: Claude edits files without asking, but asks about running commands.
  • Auto: a separate AI model checks each action, and Claude only asks you about risky ones.
  • Plan: Claude only writes a plan, which you can review and modify before Claude carries it out. We’ll try this in the mini-project.

We’ll stick to Manual mode for most of today: it’s slower-going, but you’ll see exactly what Claude does. Once you’re comfortable reviewing Claude’s work, the many permission requests can become tedious, and it’s easy to start clicking “Yes” without reading what you approve. At that point, Auto mode is a good alternative.

ImportantClaude runs its own R

Claude does not use the R session in your Positron console. When it runs a script, it starts a separate R process with Rscript, which means that:

  • Its plots don’t appear in your Plots pane, and the objects it creates don’t appear in your Variables pane.
  • It can’t see objects you created in the console. Anything it needs should be in a script or a file.

To see the results in Positron, simply run the script yourself.

5 File context, and interrupting Claude

5.1 Giving Claude your files as context

A key advantage of using AI inside your editor is that your files are readily available. Your entire workspace (the folder you opened in Positron) is “implicit” context: when Claude thinks it’s useful, it will search and read files there by itself.

But when you have specific files in mind, it’s often better to point Claude to them explicitly. That’s faster and cheaper, and avoids Claude guessing which files you mean:

  • The file that’s active in the editor is added automatically: you can see its name below the prompt box5.
  • You can also select specific lines in the active file, to focus Claude’s attention on them.
  • Type @ followed by part of a file name to add any file in your workspace.
  • To add multiple files, type @ for each, or press Alt/Option+K with a file active in the editor.

5.2 Stopping, steering, and rewinding

Sometimes you need to adjust what Claude is doing while it’s working:

  • Steer it: type a new message while Claude is working, and it will take that into account after a few seconds. (It helps to keep an eye on Claude’s intermediate messages!)
  • Stop it: press Esc or click the stop button.
  • Rewind: press Esc twice in quick succession, or hover over an earlier message and click the rewind button, to go back to an earlier point in the conversation and optionally undo file changes. (Claude is also good at undoing things when you simply ask it to.)

6 Persistent instructions with CLAUDE.md

6.1 Persistent instructions: why and how

Each new conversation with Claude starts from scratch: it doesn’t see what you discussed in earlier conversations. So you may find yourself repeatedly telling it the same things, such as “never modify the raw data”, “use the native pipe”, or “don’t use setwd()”.

Instead, you can put these kinds of instructions in a file called CLAUDE.md, a Markdown file that Claude automatically reads at the start of every conversation in your project (if you’re not familiar with Markdown, you can simply consider it a plain text file when you write in it). There is no required structure for its contents, but it should be concise and easy to read, for you as well as for Claude.

As a first example, create a new file CLAUDE.md in your project folder, add the following line to it, and save it:

CLAUDE.md
- Always answer like an overexcited sports commentator

Then, close the file (because any active file would be added to the prompt anyway, even if it wasn’t a CLAUDE.md file!), start a new conversation, and ask:

What’s the difference between <- and = in R?

6.2 Our instructions for this project

Replace the sports commentator line with the following:

CLAUDE.md
## R conventions

- Use paths relative to the project folder, and never use `setwd()`
- Use the tidyverse and the native pipe `|>`
- I'm an intermediate R user: prefer readable over clever code,
  and briefly explain non-obvious steps in comments
- Test R code by running it with `Rscript`, and Quarto documents with `quarto render`
- Ask before installing R packages
- Don't run Shiny apps yourself, since they keep running: I will run them

We’re leaving out any information about our data here, so we can see what Claude figures out by itself in the mini-project below. In a real research project, though, it’s worth adding sections that briefly describe your data files, your project’s file structure, and so on. As another example, you may want all your plots to have a certain theme, or to use a certain color palette, and you can put that in CLAUDE.md too.

Close the file again, and to check that Claude picks up the new instructions, start a new conversation and ask:

What rules should you follow in this project?

The response I got is in the screenshot on the right.

We’ll see these instructions in action in the mini-project below.

ImportantWindows users: tell Claude where Rscript is (Click to expand)

On Windows, R’s installer doesn’t make Rscript available to commands run outside of R, so Claude may struggle to find it. To help it, run the following in the Positron console:

normalizePath(file.path(R.home("bin"), "Rscript.exe"), winslash = "/")

And add the resulting path to the “R conventions” section of your CLAUDE.md, e.g.:

CLAUDE.md (excerpt)
- Rscript is at `C:/Program Files/R/R-4.5.1/bin/Rscript.exe`
NoteMore on using CLAUDE.md (Click to expand)

Drafting a CLAUDE.md with /init
Instead of writing a CLAUDE.md from scratch, you can type /init in the prompt box: Claude then looks through your project and drafts a CLAUDE.md for you to review and edit. This can be a useful start in a larger existing project, but the most valuable parts of a CLAUDE.md are things only you know: what the project is about, where the data is, and how you want things done.

Keep updating your CLAUDE.md
Start simple, and add to it whenever you notice yourself telling Claude the same thing again, or Claude making the same mistake again. Keep it short, though: it’s read at the start of every conversation, so it uses up tokens (and money) each time.

Instructions are not strict rules
Claude will usually but not always follow the instructions in CLAUDE.md.

Claude’s memory
Claude also keeps memory notes for itself: when you correct it or tell it about your preferences, it may save a note, which is loaded into future conversations in the same project. Type /memory in the prompt box to see and edit these.

7 Mini-project: from a messy CSV to a report and an app

We’ll work with the “factbook” data from the previous session, World Bank data that is now in factbook.csv. We’ll have Claude clean it, and then build a report and an app on top of the cleaned data.

7.1 A quick look at the data

First, let’s take a quick look at the data: click on factbook.csv in the Explorer pane to open it in the Data Explorer.

Scroll around, including to the bottom of the file, and you’ll see a few things that make the data awkward to work with:

  • It is in a “wide” format, with one column per year.
  • The year column names, like 2000 [YR2000], are not just numbers.
  • The year columns are text rather than numbers, because missing values are coded as ...
  • The last rows are not data, but empty rows and notes about the database.

Let’s see how Claude handles this.

We’ll start a new conversation for each step below. Thanks to the CLAUDE.md file and the files Claude creates along the way, it doesn’t need to remember the previous conversation.

7.2 Clean the data

Write clean-factbook.R that reads factbook.csv and saves a tidy version to factbook_tidy.csv with columns country, country_code, indicator, year (numeric), and value. Check the result.

Some things to watch for in its reply, the code, and the resulting factbook_tidy.csv:

  • How does Claude look at the data before writing code?
  • Did it figure out the .. missing values and the odd year column names by itself?
  • Did it notice the notes at the bottom of the file, which aren’t data? (Check the last rows of the tidy file.)
  • How did it “check the result”?
  • Is the code clear and does it have explanatory comments?

Let’s ask for one follow-up change:

Add a continent column

It’s likely that Claude will want to use the countrycode package to do this, and following our CLAUDE.md instructions, it will ask for permission to install the package first:

Let’s take another quick look at the data in the Data Explorer, to see if the continent column looks right.

clean-factbook.R
library(tidyverse)
library(countrycode)

# Read everything as character first, because the `..` missing-value
# code would otherwise turn the year columns into text anyway
factbook <- read_csv("factbook.csv", col_types = cols(.default = "c"))

factbook_tidy <- factbook |>
  # The file ends with blank and footnote rows that have no country: remove them
  filter(!is.na(`Country Code`)) |>
  # Drop the series code; keep the readable indicator name
  select(
    country = `Country Name`,
    country_code = `Country Code`,
    indicator = `Series Name`,
    starts_with("20")
  ) |>
  # Wide -> long: one row per country x indicator x year
  pivot_longer(
    cols = starts_with("20"),
    names_to = "year",
    values_to = "value"
  ) |>
  mutate(
    # Column names look like "2000 [YR2000]": keep the first 4 characters
    year = as.numeric(str_sub(year, 1, 4)),
    # `..` marks missing values: turn into NA, then convert to numbers
    value = as.numeric(na_if(value, "..")),
    # Look up the continent from the ISO3 country code; Kosovo (XKX) and the
    # Channel Islands (CHI) have no standard match, so we set them manually
    continent = countrycode(
      country_code,
      origin = "iso3c",
      destination = "continent",
      custom_match = c(XKX = "Europe", CHI = "Europe")
    ),
    .after = country_code
  )

write_csv(factbook_tidy, "factbook_tidy.csv")

library(tidyverse)
library(ggiraph)

factbook <- read_csv("factbook_tidy.csv")

# One colour-blind-safe colour per continent
continent_cols <- c(
  Africa = "#D55E00",
  Americas = "#0072B2",
  Asia = "#009E73",
  Europe = "#CC79A7",
  Oceania = "#E69F00"
)

# One row per country with the 2000 and 2015 life expectancy
life <- factbook |>
  filter(
    indicator == "Life expectancy at birth, total (years)",
    year %in% c(2000, 2015)
  ) |>
  select(country, continent, year, value) |>
  pivot_wider(names_from = year, values_from = value, names_prefix = "y") |>
  drop_na(y2000, y2015) |>
  mutate(
    tip = str_glue(
      "{country} ({continent})\n2000: {round(y2000, 1)} years\n2015: {round(y2015, 1)} years\nGain: {round(y2015 - y2000, 1)} years"
    )
  )

p_life <- ggplot(life, aes(y2000, y2015, colour = continent)) +
  geom_abline(
    slope = 1,
    intercept = 0,
    linetype = "dashed",
    colour = "grey40"
  ) +
  # data_id = continent: hovering one country highlights its whole continent
  geom_point_interactive(
    aes(tooltip = tip, data_id = continent),
    alpha = 0.8,
    size = 2.2
  ) +
  scale_colour_manual(values = continent_cols, name = NULL) +
  labs(
    title = "Almost every country gained years of life",
    subtitle = "Dashed line = no change",
    x = "Life expectancy in 2000 (years)",
    y = "Life expectancy in 2015 (years)"
  ) +
  theme_minimal(base_size = 13) +
  theme(
    plot.title = element_text(face = "bold"),
    plot.title.position = "plot",
    panel.grid.minor = element_blank(),
    legend.position = "bottom"
  )

girafe(
  ggobj = p_life,
  width_svg = 8,
  height_svg = 5,
  options = list(
    opts_hover(css = "fill-opacity:1; stroke-opacity:1; stroke-width:2px;"),
    opts_hover_inv(css = "opacity:0.2;"),
    opts_tooltip(
      css = "background:white; color:#222; padding:6px 8px;
                        border-radius:4px; box-shadow:0 1px 4px #0006;"
    )
  )

8 Appendix

8.1 Agents fill up the context window quickly

A model’s context window holds everything in the conversation, and performance degrades as it fills up. With an agent, this happens much faster than with a chatbot: every file Claude reads and every command output it sees goes into the context too. To see how full the context window is, type /context in the prompt box.

8.2 Start fresh often

Today, we’ve started a new conversation for each new task. That’s a good habit: Claude can get confused when you switch topics within a conversation, and a long conversation is slower and more expensive, because with every new prompt, the entire conversation is sent to the model again.

To make re-sending the conversation cheaper, the part that hasn’t changed since the previous turn is cached, and cached tokens cost only about one tenth of the regular price. However, with an API key like ours, the cache expires after only 5 minutes without activity — the clock icon in the prompt box shows how much time is left. After that, your next message reprocesses the entire conversation at the full price. So when you come back to a long conversation after a break, consider starting a new one instead.

If you do want to continue a long conversation, type /compact in the prompt box: Claude then replaces the conversation so far with a summary, which frees up context.

8.3 Cost

Every token costs money, and your API key has a limited budget. To see an estimate of what the current conversation has cost so far, type /usage in the prompt box.

To keep costs down:

  • Stick to Sonnet at Medium effort (the default in your settings file).
  • Start fresh for each new task, and point Claude to specific files.
  • Don’t ask Claude to “read” or “analyze” large data files: have it write code that does the analysis instead.
  • For general questions, like explaining a concept or a function, a browser-based chat (e.g. Gemini or Copilot through your OSU account) works just as well and doesn’t use your API key’s budget.
NoteAPI pricing vs. personal subscriptions (Click to expand)

Paying per token through an API key, as we do here, is much more expensive than a personal subscription to a service like Claude, which has a fixed monthly fee. A day of heavy agentic coding through an API can easily cost more than a month’s subscription. However, personal accounts are not approved for institutional data, which includes your unpublished research data.

8.4 Good habits when working with an agent

Getting good help

  • Be explicit. Point Claude to the relevant files, and put your conventions and rules in CLAUDE.md.
  • Start fresh for each new task, and keep conversations focused.
  • Use Plan mode for bigger tasks, and review the plan before Claude starts.

Checking and keeping the results

  • You own the result. Read every proposed edit and command before approving it.
  • Verify, don’t trust. When Claude says something “works”, that may be a prediction rather than a test result. Run the code yourself, and check results independently.
  • Results should come from code you can rerun. Let Claude help you write code that you review, run, and keep; don’t rely on numbers or conclusions it only reports in the chat.
  • Commit before, review after. Use Git so that you can see and undo what Claude changed (Positron’s Source Control view makes this easy).
  • Keep a record of how you used AI, which journals increasingly ask you to disclose (see the box below).

Bonus exercise: Fix a script

The script penguin_summary.R should compute the number of penguins and their mean body mass, for Adelie and Gentoo penguins, but it has two problems.

  Click to see the script’s code 
penguin_summary.R
# Summarize body mass for Adelie and Gentoo penguins
# (uses the penguins data that is built into R 4.5.0 and later)

library(tidyverse)

# Keep only Adelie and Gentoo penguins
two_species <- penguins |>
  filter(species == c("Adelie", "Gentoo"))

# Number of penguins and mean body mass per species
two_species |>
  group_by(species) |>
  summarize(
    n = n(),
    mean_mass_g = mean(body_mass)
  )

  1. Open the script and run it. What’s wrong with the output?

      Click to see the output

     
    # A tibble: 2 × 3
species     n mean_mass_g
<fct>   <int>       <dbl>
1 Adelie     76       3407.
2 Gentoo     62         NA

  2. Start a new conversation, and with the script open, ask Claude:

    Explain what this script does

    Does its explanation match your own understanding?

    It may well have pointed out one or two problems with the script, and if it did, it may have offered to fix them. If so, affirm that you want it to fix the problem(s) it found.

  3. In case Claude didn’t note the problem that produces the NA in the output, ask:

    I ran this and the mean body mass for Gentoo is NA. Fix it.

    It should be able to identify and fix this problem, and if it hadn’t already fixed the other problem, it may fix that too.

  4. Run the script yourself. If the results are like this, the problems are fixed:

    # A tibble: 2 × 3
species     n mean_mass_g
<fct>   <int>       <dbl>
1 Adelie    152       3701.
2 Gentoo    124       5076.

    If not, ask Claude to look for another problem.

Click here for the solution

The script contains two errors:

  • mean() returns NA when there are any missing values, unless you use na.rm = TRUE. This is easy to spot, because the output contains an NA.

  • species == c("Adelie", "Gentoo") does not check whether species is one of these two values. Instead, R “recycles” the two-element vector along all rows, comparing row 1 to "Adelie", row 2 to "Gentoo", row 3 to "Adelie", and so on. As a result, about half of the Adelie and Gentoo penguins are silently dropped. The fix is to use %in% instead of ==.

The second error is the more dangerous one, because it silently produces wrong results: there is no error or warning, and the output looks plausible. Before the fix, the script reports 76 Adelie and 62 Gentoo penguins, whereas there are 152 and 124.

two_species <- penguins |>
  filter(species %in% c("Adelie", "Gentoo"))

two_species |>
  group_by(species) |>
  summarize(
    n = n(),
    mean_mass_g = mean(body_mass, na.rm = TRUE)
  )

Did Claude catch the second error? It may have noticed it while reading the script, after running it and seeing suspicious counts, or not at all. This shows why code that runs without errors still needs to be checked, whether you or Claude wrote or fixed it.
