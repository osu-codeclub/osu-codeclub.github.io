Getting Started with Positron

A guided tour of Posit’s new data science IDE – and what changes when you come from RStudio

1 Introduction

1.1 What we’ll cover

Every Code Club session so far has used RStudio. Today we’ll spend the session in a different program: Positron, a newer data science IDE from Posit — the same company that makes RStudio.

The goal today is orientation, not mastery. By the end of the session you should be able to open your own work in Positron, find your way around, and decide for yourself whether you want to keep using it. Specifically, we’ll cover:

  • Installing Positron and opening a folder — including the fact that there is no equivalent of an .Rproj file
  • Touring the interface — what happened to each of your RStudio panes, and the one new habit that makes everything else easier
  • Exploring data — the Data Explorer, Variables pane, and Packages pane
  • Making Positron feel like home — keyboard shortcuts, settings, and extensions

We’ll do all of this with a single dataset, so the session feels like doing actual work rather than clicking around an empty program.

1.2 Why is there a new IDE?

RStudio was built, first and foremost, for R. That was a great decision in 2011, and it is why RStudio is so good at what it does. But a lot of data scientists now move between R, Python, and SQL in the same project, and retrofitting RStudio for that turned out to be harder than starting fresh.

So Posit started fresh. Positron is built on Code OSS, the open-source core of Visual Studio Code, with data science features added on top. That gives it a modern editor, an enormous extension ecosystem, and first-class support for several languages at once — while keeping the things R users expect, like a Console, a Variables pane, and a Plots pane.

ImportantIs RStudio going away?

No. Posit has committed to maintaining and updating RStudio.

What is true is that major new features are now going to Positron first. So this is not “RStudio is being switched off next year”, it is more like “the interesting new stuff is happening over there”.

You do not have to switch today, or ever. But it’s worth knowing what your options are.

1.3 Before we start

If you haven’t done so already, please:

  1. Install Positron from https://positron.posit.co/download.html. It’s free, and there are installers for Windows, macOS, and Linux.

  2. Make sure you have a recent R (4.4.0 or higher) installed — the same R installation you already use for RStudio is fine. Positron does not come with its own copy of R.

  3. Install two R packages, if you don’t have them. You can do this from RStudio, before the session:

    install.packages(c("tidyverse", "nycflights13"))
WarningUsing an OSU-managed computer?

You may not have the administrative privileges needed to install software. Try the “Software Center” (Windows) or “Ohio State Application Self Service” (Mac) app on your computer first.

Note that, unlike RStudio, Positron is not currently available at OSC, so there is no browser-based fallback. If you can’t get it installed, don’t worry — pair up with a neighbor, or just follow along and try it later. The material on this page will stay available.

2 Getting started

2.1 Opening a folder — and the missing .Rproj

Start Positron. You’ll get a Welcome screen with an Open Folder button (you can also use File > Open Folder...).

This is the first real difference from RStudio, and it’s worth pausing on. Back in our session on RStudio Projects, we made a big deal of .Rproj files: they mark a folder as a project, and opening one sets your working directory and gives you a clean R session.

Positron has no .Rproj equivalent. Instead, any folder you open is treated as the project. Opening a folder sets your working directory to that folder and gives you a fresh R session — you just don’t need a special file to make it happen.

TipThe good news

Everything you learned about why projects are useful still applies:

  • Keep each analysis in its own self-contained folder
  • Use paths relative to the folder root, never setwd()
  • The here package still works exactly as before

And if you open a folder that already contains an .Rproj file, nothing breaks — Positron simply ignores the file. So a folder can work as both an RStudio Project and a Positron workspace, which is handy while you’re trying Positron out.

For today, make a new, empty folder somewhere sensible (e.g. ~/Documents/codeclub/positron) and open it in Positron.

2.2 Starting an R session

Look at the top-right corner of the window: that’s the interpreter picker. If Positron found your R installation, it may have started a session already. If not, click the picker and choose your version of R.

The picker lists every interpreter Positron can find — possibly several versions of R and Python. Switching between R versions is a single click here, which is considerably less painful than it is in RStudio.

You can also have several sessions running at once (say, an R session and a Python session, or two R sessions on different R versions) and switch between them from this same menu.

Once a session is running, the Console works the way you’d expect. Try it:

1 + 1
sessionInfo()

2.3 Our dataset for today

We’ll use the flights dataset from the nycflights13 package: every flight that departed New York City in 2013. It has about 337,000 rows and 19 columns, which matters — several of the things we’ll look at today only become interesting once a dataset is too big to eyeball.

Create a new R script (File > New File > R File, or Cmd/Ctrl+N), save it as explore.R, and add:

library(tidyverse)
library(nycflights13)

# Make a copy of the data as a CSV file, so we have a data file to work with
dir.create("data")
write_csv(flights, "data/flights.csv")

# Read it back in
flights_df <- read_csv("data/flights.csv")

Run the code with Cmd/Ctrl+Enter — same shortcut as RStudio. As in RStudio, this runs the current line (or your selection) and moves the cursor down.

That write_csv() line produces a ~30 MB file. We’re doing it deliberately: later on we’ll open that file directly, without any R code at all, which is something RStudio simply can’t do.

3 A tour of the interface

Positron’s layout will feel broadly familiar — you write code in an editor, run it in a console, and look at results in panes — but things have moved, and there are two regions that have no RStudio equivalent.

3.1 The five regions

Region Where What’s in it
Editor Center Your scripts and documents, in tabs
Console Bottom The R console, plus the Terminal — as in RStudio
Activity Bar Far left Icons that switch what the Primary Side Bar shows
Primary Side Bar Left Explorer (files), Search, Source Control (git), Extensions, Packages
Secondary Side Bar Right Variables, Plots, Help, Viewer, Connections

The Activity Bar is the genuinely new idea. In RStudio, every pane is visible at once in a fixed 2x2 grid. In Positron, the left-hand side bar shows one thing at a time, and you click an icon in the Activity Bar to change which. That feels cramped at first and spacious later, once you stop needing four things visible simultaneously.

TipDon’t like the layout? (Click to expand)

Almost every pane in Positron can be dragged somewhere else. If you want your Help pane down at the bottom next to the Console, just drag its tab there.

There are also preset layouts: open the Command Palette (see below) and search for Positron: layout commands to try a couple of alternatives.

3.2 Where did my RStudio pane go?

3.3 The Command Palette

If you take one thing away from today, make it this one.

Press Cmd+Shift+P (Mac) or Ctrl+Shift+P (Windows/Linux). A search box appears at the top of the window. Start typing what you want to do, and Positron will fuzzy-match it against every command it knows.

This replaces a lot of RStudio’s buttons and menus. Rather than learning where things live, you learn to describe what you want:

  • Type restart → Interpreter: Restart Active Interpreter Session
  • Type packages → View: Packages
  • Type theme → Preferences: Color Theme
  • Type settings → Preferences: Open Settings (UI)
TipIt teaches you shortcuts, too

The Command Palette shows the keyboard shortcut next to each command that has one. So it’s also how you discover shortcuts: find the command by name, notice the shortcut, and next time skip the palette.

This is much more reliable than memorizing a list — and it’s why this page doesn’t give you one.

Exercise 1: Find your way around

Using only the Command Palette (no menus, no clicking around!), do the following:

  1. Open the Packages pane

  2. Change the color theme to something you like better than the default

  3. Restart your R session, then confirm in the Variables pane that your objects are gone

  4. Re-run your script to get flights_df back (hint: there’s a command for running the whole file — find it!)

Click here to see hints

For each of these, open the palette with Cmd/Ctrl+Shift+P and type:

  1. packages — look for View: Packages
  2. theme — look for Preferences: Color Theme, then use the arrow keys to preview themes live before hitting Enter
  3. restart — look for Interpreter: Restart Active Interpreter Session
  4. run — look for R: Run R File in Console or similar

Notice how each of these showed you a keyboard shortcut on the right-hand side.

4 Exploring data

This is where Positron most clearly does something RStudio doesn’t.

4.1 The Variables pane

Look at the Variables pane on the right. It’s RStudio’s Environment pane, with one big improvement: you can expand objects to look inside them, by clicking the arrow next to an object’s name.

Try expanding flights_df. You’ll see each column, its type, and a preview of its contents — without having to write str() or glimpse().

4.2 The Data Explorer

Now for the main event. In the Variables pane, find flights_df and click the small table icon next to it.

📸 SCREENSHOT NEEDED: the Data Explorer open on flights_df, with the summary panel and filter bar visible. Save as img/data-explorer.png.

The Data Explorer opens as a tab in the Editor, not as a small pane. It has three parts:

  • The data grid — the spreadsheet-like view of your rows and columns
  • The summary panel — per-column statistics and a small distribution plot
  • The filter bar — for temporarily filtering rows
NoteThis is not View() with a new coat of paint

RStudio’s View() lets you sort and do simple per-column filtering. What it doesn’t give you is summary statistics, and that’s the real difference here.

Scroll through the summary panel for flights_df and notice, for free: the percentage of missing values per column, min/median/max for numeric columns, and the number of distinct values for character columns. dep_delay and arr_delay have a few percent missing — those are the cancelled flights, and you found that out without writing any code.

Sorting and filtering

  • Sort by clicking a column header
  • Filter by clicking + Add Filter in the filter bar, picking a column, and choosing a condition

Filters stack: add several and they combine. Crucially, none of this modifies your data — it’s a temporary view, so you can explore freely without worrying about messing something up. When you’ve worked out what you want, you write the actual filter() call in your script.

Opening data files directly

Here’s the part with no RStudio equivalent at all.

Open the Explorer in the Activity Bar (the top icon, looks like documents), find data/flights.csv, and double-click it.

It opens in the Data Explorer. No R session involved, no read_csv(), no waiting for a 30 MB file to load into memory.

TipWhich file types?

.csv, .tsv, .parquet, and .xlsx — plus compressed versions of CSV, TSV, and Parquet.

This is genuinely useful for the “what is this file someone sent me?” problem, especially when the file is too big to open in Excel.

4.3 Plots and Help

Make a plot, so we have something to look at:

flights_df |>
  filter(!is.na(arr_delay)) |>
  ggplot(aes(x = arr_delay)) +
  geom_histogram(bins = 100) +
  scale_x_continuous(limits = c(-100, 300)) +
  labs(x = "Arrival delay (minutes)", y = "Number of flights") +
  theme_bw()

The Plots pane behaves much like RStudio’s, including the back/forward arrows through your plot history. Two things to try: the expand button, which pops the plot out into a large editor tab, and the size controls, which let you set specific plot dimensions rather than resizing a pane by hand.

For Help: put your cursor inside a function name in your script — say, geom_histogram — and press F1. The Help pane opens with the documentation. ?geom_histogram in the Console still works too.

4.4 The Packages pane

Open the Packages pane from the Activity Bar.

This is a recent addition and a nice one. It lists every package installed in your current session’s library, with:

  • its version, and whether it’s attached (i.e. you ran library() on it)
  • a filter to show only outdated packages
  • buttons to install, update, and remove packages
  • links to each package’s documentation and website

Try filtering to outdated packages to see what you’ve been neglecting.

After installing or updating a package, Positron will offer to restart your session. Say yes — this is the same reason RStudio asks you to restart R after updating a package that’s currently loaded.

Exercise 2: Explore the flights data

Use the Data Explorer — not R code — to answer these:

  1. Which column has the most missing values? (Hint: the summary panel shows a missing-value percentage per column.)

  2. How many distinct airline carriers (carrier) are in the data?

  3. Filter to flights that departed from JFK and had a departure delay (dep_delay) of more than 120 minutes. Roughly how many rows are left? (Look for the row count displayed in the Data Explorer — it reflects your active filters.)

  4. Sort those filtered flights by dep_delay, descending. What was the single worst departure delay out of JFK, in hours?

Then: write the R code that reproduces your filter from step 3, and check that you get the same number of rows.

Click here to see the solution to the last part 
flights_df |>
  filter(origin == "JFK", dep_delay > 120) |>
  nrow()

This is a workflow worth getting used to: explore interactively in the Data Explorer, then write the code that makes it reproducible. The clicking is for figuring out what you want; the code is what goes in your script.

5 Making Positron feel like home

The single biggest complaint from RStudio users trying Positron is “my keyboard shortcuts don’t work”. Let’s fix that, and a few other things.

5.1 Get your RStudio keybindings back

Many RStudio shortcuts already work in Positron — Cmd/Ctrl+Enter to run code, Cmd/Ctrl+L to clear the console. But plenty don’t, because Positron inherits VS Code’s shortcuts, which sometimes conflict.

There’s a single setting that fixes most of this. Open the Command Palette and run Preferences: Open Settings (UI), then search for rstudioKeybindings and check the box:

"workbench.keybindings.rstudioKeybindings": true

Restart Positron for it to take effect.

This turns on a large set of RStudio shortcuts, including:

Shortcut Action
Ctrl+1 Focus the Source/Editor pane
Ctrl+2 Focus the Console
F2 Go to definition
Ctrl+Shift+R Insert a section header

5.2 Settings: the UI and the JSON file

Positron has a lot of settings — inherited from VS Code, plus its own. There are two ways to change them, and they edit the same thing:

  • Settings UI — Preferences: Open Settings (UI). Searchable, with checkboxes and dropdowns. Start here.
  • settings.json — Preferences: Open User Settings (JSON). The raw file. Faster once you know what you’re looking for, and easy to copy between computers.
TipUser settings vs. workspace settings

Settings come in two levels:

  • User settings apply everywhere — your personal preferences
  • Workspace settings apply only to the current folder, and get saved in a .vscode/settings.json file inside it

The workspace level is genuinely useful for collaborative projects: you can commit a .vscode/settings.json so everyone working on the project gets the same formatting behavior.

5.3 A few settings worth changing

These are the ones RStudio refugees most often want:

{
  "workbench.keybindings.rstudioKeybindings": true,
  "files.trimTrailingWhitespace": true,
  "files.insertFinalNewline": true,
  "editor.wordWrap": "on",
  "files.autoSave": "afterDelay"
}
  • trimTrailingWhitespace / insertFinalNewline — tidier files, and much cleaner git diffs
  • editor.wordWrap — soft-wrap long lines instead of scrolling sideways
  • files.autoSave — saves automatically; some people love this, others hate it, try it and see

5.4 Extensions

Positron can install VS Code extensions, which is a large part of the appeal. Open the Extensions view from the Activity Bar and search.

Some worth knowing about:

Extension What it does
Quarto Quarto support (usually installed already)
Shiny Run and debug Shiny apps
Rainbow CSV Colorizes CSV columns when viewing as plain text
Indent Rainbow Colorizes indentation levels
Tomorrow Night Bright (R Classic) The RStudio theme, ported

Not everything transfers. RStudio add-ins are not compatible with Positron — if you rely on something like datapasta or styler’s add-in buttons, check whether a Positron/VS Code equivalent exists before you switch.

Exercise 3: Make it yours

Spend a few minutes setting Positron up the way you would want it:

  1. Turn on RStudio keybindings (and restart Positron)

  2. Pick a color theme you actually like

  3. Change at least two other settings from the list above — or find your own by browsing the Settings UI

  4. Install one extension that looks useful to you

Then compare with the person next to you: what did they change that you didn’t think of?

Bonus exercise: Bring your own project

If you finish early — or want something to do afterwards — this is the real test:

  1. Open one of your own project folders in Positron (File > Open Folder...). An existing RStudio Project folder is fine.

  2. Run one of your own scripts.

  3. Note down anything that doesn’t work or that you can’t find.

Bring that list to a future Code Club session or email it to us — it’s exactly the kind of thing worth working through as a group.

6 Wrapping up

6.1 What we didn’t cover

Positron does considerably more than we had time for today:

  • AI assistance with Posit Assistant — chat, code generation, and agentic tools, built right into Positron. This is the topic of our next session on September 17, with Jess!
  • Quarto — rendering, and inline output for .qmd files
  • Git — via the Source Control view in the Activity Bar
  • Notebooks — Positron has its own Jupyter notebook editor
  • Databases — the Connections pane, for DuckDB, PostgreSQL, SQLite and more
  • Python — the whole other half of what Positron is for

6.2 So, should you switch?

An honest summary.

Reasons to switch:

  • The Data Explorer is a real improvement over View()
  • Effortless handling of multiple R versions and multiple sessions
  • If you use Python at all, one IDE instead of two
  • The extension ecosystem is enormous
  • New Posit features land here first

Reasons to wait:

  • R Markdown support is thinner than in RStudio (Positron favors Quarto), and Sweave is not supported
  • RStudio add-ins don’t work
  • Some R-specific niceties are still RStudio-only
  • Your muscle memory is worth real money, and rebuilding it costs a few weeks

There’s no wrong answer, and no deadline. A reasonable middle path: keep using RStudio for your real deadlines, and open Positron for your next new project.

6.3 Where to get help

  • The Positron documentation — and note that most VS Code documentation also applies, since Positron is built on it
  • The migration guide for RStudio users
  • An in-product walkthrough: open the Command Palette, run Welcome: Open Walkthrough…, and pick “Migrating from RStudio to Positron”
  • The Positron GitHub repo, where you can report bugs and see what’s coming
  • Any of the Code Club organizers — do ask!
